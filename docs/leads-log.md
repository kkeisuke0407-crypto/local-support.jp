# 依頼者・案件台帳（leads log）

ロカサポに入った見積依頼（リード）を1案件1ブロックで管理する台帳。
フォーム見積依頼 → support@ 着信 → 本台帳に起票 → 業者打診 → 見積回収 → 依頼者へ返信、までを1枚で追う。

> 運用ルール
> - 新規依頼が来たら **まず本台帳に起票**（受信箱に埋もれさせない）
> - 案件IDは `PCO-YYYY-MMDD-NNN`（サービス略号＋受付日＋連番）。例: 害虫=PCO / 受水槽=WTK / アスベスト=ASB 等
> - 連絡先など個人情報は最小限に。詳細は support@ の受信箱を正とし、ここには要点のみ
> - ステータスが動いたら「最終更新」を必ず書き換える

## ステータス定義
`起票` → `業者打診準備` → `業者打診中` → `見積回収中` → `依頼者へ提示` → `成約` / `失注` / `保留`

## トラッカー運用 — Googleスプレッドシート1枚・2タブ（正本／codex共有）

進捗管理は **Googleスプレッドシート1ファイル＝2タブ**を正本とする（運用方針A）。

| タブ | 単位 | seed CSV | 用途 |
|---|---|---|---|
| `案件` | 1案件1行 | `docs/sheet-tab1-cases.csv` | 依頼者・案件のステータス俯瞰 |
| `業者見積` | 1（案件×業者）1行 | `docs/sheet-tab2-quotes.csv` | 業者ごとの見積依頼状況・概算金額 |

- **正本**：Googleスプレッドシート（2タブ）。リポジトリの2つのCSVは**各タブの作成用seed**（正本ではない）
- このmarkdown（leads-log.md）は**経緯メモ**。最新ステータスはスプシを見る
- codexにも「進捗はスプシを正として読み書き。タブは `案件` と `業者見積` の2枚」と共有すること

### 列定義
- `案件`タブ：`案件ID, 受付日, 依頼者名, サービス, エリア, 要件サマリ, 延床面積, HACCP, 希望頻度, ステータス, 担当, 最終更新, 打診数, 見積回収数, 成約, 紹介手数料, 備考`
- `業者見積`タブ：`案件ID, 業者名, 業者URL, 区分, 依頼担当, 依頼日, 依頼方法, 見積ステータス, 概算最小, 概算最大, 要現地調査, 回答日, 採用可否, 次アクション, 備考`
- 2タブは `案件ID` で紐づく

### codexとユーザーの衝突防止ルール（重要）
「どちらでも業者へ見積依頼する」運用のため、`業者見積`タブで次を徹底する。
- **送信前に必ず `依頼担当` へ自分の名前（ユーザー/codex）を記入し、`見積ステータス` を `依頼済` に更新**（先に確保＝二重送信防止）
- `依頼担当=未割当` かつ `見積ステータス=未依頼` の行だけが「未着手」。ここから取る
- 見積が返ったら `見積ステータス`→`見積受領`、`概算最小/最大`・`回答日`・`採用可否` を記入
- 案件の状況が動いたら `案件`タブの `ステータス`・`打診数`・`見積回収数`・`最終更新` も更新

### 見積ステータスの値
`未依頼` / `依頼済` / `見積受領` / `要現地調査` / `辞退` / `不通` / `採用` / `見送り`

### スプシの構築手順（2タブ）
1. 本体スプシ：既存の「案件トラッカー」を流用（タブ名を `案件` に変更）
2. ファイル → インポート → `docs/sheet-tab2-quotes.csv` → **「新しいシートを挿入」** → タブ名を `業者見積` に
3. 共有 → codex運用者を編集者に追加
4. 不要な先行スプシ（分割の見積依頼版・フラット統合版）は削除
